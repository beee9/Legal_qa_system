## 🐛 故障排查

### 问题 1：策略选择失败

**症状**：日志显示 "策略选择失败，使用默认策略"

**原因**：
- API 额度用完
- 网络连接失败

**解决**：
1. 检查 API Key 和额度
2. 系统会自动回退到"直接检索"
3. 不影响正常使用

### 问题 2：子查询检索慢

**症状**：子查询检索耗时超过 5 秒

**原因**：
- 子查询数量过多
- 每个子查询需要独立检索

**解决**：
```python
# 在 base/config.py 中调整
self.MAX_SUBQUERIES = 2  # 限制最大子查询数量（默认 3）
```

### 问题 3：HyDE 生成答案不准确

**症状**：假设答案偏离查询意图

**原因**：
- Prompt 需要优化
- LLM 模型理解偏差

**解决**：
1. 调整 `legal_rag_prompts.py` 中的 HyDE Prompt
2. 或手动指定使用"直接检索"策略

## 💡 最佳实践

### 1. 何时使用手动策略

**推荐场景**：
- 已知查询类型，跳过策略选择节省时间
- 策略选择不准确时的临时方案
- A/B 测试不同策略效果

**不推荐场景**：
- 用户输入查询（让系统自动选择）

### 2. 如何优化 Prompt

**子查询分解**：
- 强调"独立问题"
- 添加示例
- 限制子查询数量

**HyDE 生成**：
- 强调"法律专业语言"
- 包含关键术语
- 控制生成长度

**回溯简化**：
- 提取核心要素
- 保留关键信息
- 使用专业术语

### 3. 性能优化建议

**并行执行**：
```python
# 子查询检索可并行化（未来优化）
import asyncio

async def parallel_search(subqueries):
    tasks = [search_async(sq) for sq in subqueries]
    return await asyncio.gather(*tasks)
```
