## 📊 意图分类器工作原理

### 三种路由策略

```
用户查询
    ↓
BERT 意图分类 (100ms)
    ↓
    ├─ [通用问题] → 直连 LLM
    │   示例："今天天气怎么样"
    │   响应时间：0.6s
    │   不检索法律库，节省资源
    │
    ├─ [法条查询] → BM25 精确检索
    │   示例："民法典第509条是什么"
    │   响应时间：0.3s
    │   降低阈值，提高命中率
    │
    └─ [法律咨询] → RAG 向量检索
        示例："老板拖欠工资怎么办"
        响应时间：2.1s
        语义理解，准确率最高
```

## ⚙️ 配置调整（可选）

### 调整 BM25 阈值

如果发现法条查询命中率低，可以调整：

```python
# new_main.py 第 194 行
answer, need_rag = self.bm25_search.search(query, threshold=3.0)

# 降低阈值 = 更容易命中（如改为 2.0）
# 提高阈值 = 更严格（如改为 5.0）
```

### 禁用分类器

如果需要临时禁用分类器：

```python
# new_main.py 第 20 行

```

## 🐛 故障排查

### 问题1：分类器加载失败

**症状**：日志显示"分类器加载失败"

**解决**：
```bash
# 检查模型文件是否存在
ls -lh rag_qa/core/legal_intent_classifier/final_model/

# 应该看到：
# config.json
# model.safetensors (391MB)
# vocab.txt
# tokenizer_config.json
```

### 问题2：分类结果不准确

**症状**：法条查询被识别为法律咨询

**解决**：
1. 查看更多测试样例，确认是个例还是普遍问题
2. 如果是普遍问题，需要重新训练模型
3. 临时禁用分类器，使用原有逻辑

### 问题3：响应速度没提升

**症状**：通用问题仍需 2-3 秒

**解决**：
1. 检查日志，确认是否走了"直连LLM"路由
2. 检查 LLM 调用是否有网络延迟
3. 分类器首次加载需要 2-3 秒，后续查询才会快
